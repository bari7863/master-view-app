Phase 0 詳細

データ基盤の拡張整備

完了・本番反映済み ／ 優先度最高・土台

新テーブル・DB選択肢の追加

  • 企業マスタに紐づく新テーブルのスキーマ・作成ロジックを実装(lib/master-data-schema.ts) — 担当者(master_data_contacts)・活動履歴(master_data_activities)・案件(master_data_deals)
  • ログイン成功時に上記テーブルを自動作成する仕組みを追加。失敗時はキャッシュをクリアして再試行できるようにし、失敗してもログイン自体は継続する設計
  • DB選択肢に「PostgreSQL」(ローカル開発用)を追加。ローカル実行時のみ表示され、Vercel本番では表示されない

Vercel本番環境での制限

  • スーパー管理者以外は、Vercel上では常にNeonのみ使える(画面側・API側の両方で制御)
  • Vercelプレビュー環境に実際にデプロイし、process.env.VERCELが"1"になることを実機確認済み

3DB運用(Neon=本番／Supabase=バックアップ／ローカル=開発)

  • Neon本番のmaster_data(186,069件)をスキーマ+データ丸ごとSupabase・ローカルPostgreSQLへ複製し、3DBを同一内容に統一
  • npm run sync:backup(Neon→Supabase/ローカル)・npm run sync:restore(Supabase→Neon、確認プロンプトあり)を追加
  • 注意: sync:backupは世代管理のない上書きミラー。誤ってNeonを壊した直後に実行するとバックアップも失われる

本番反映前レビューで発見・修正した既存バグ

  • export/route.ts(CSV抽出)が固定Neonのままで、DB切替を無視していた問題を修正
  • export/route.tsのスコープバイパス条件が「管理者」になっていた(他APIは「スーパー管理者」)問題を統一
  • [id]/route.ts(認証チェック皆無・DB固定)が放置されていた → 未参照であることを確認の上で削除
  • handleSwitchDatabaseがサーバー応答でなくクライアント側の要求値を使っていた問題を修正
  • BlockingLoadingOverlayがtypeof document === "undefined"ガードのみで、クライアント初回レンダリング時にも即座にcreatePortalを実行していたため Hydration failed エラーが出ていた(本番反映後に調査・特定) → マウント完了後にのみportalを出すよう修正、本番相当ビルドで解消を確認済み
